SSH agent and git signing

Your SSH keys live in Hisar. Every use asks first.

Point SSH_AUTH_SOCK at Hisar and keep using ssh, git and your editor. The dialog tells you which app is asking, the processes behind it, who signed it, and what it wants to do: the host, or the commit you're signing. An unsigned binary says so, loudly.

hisar run

Commit the .env. It holds no secrets.

Name a secret with a hisar:// reference instead of pasting it. hisar run resolves every reference in one request, you approve once, and the command gets the real values in its environment. Nothing is written to disk, and any value it prints comes out concealed.

{% call code_block("Example .env file", "light") -%} # .env DATABASE_URL=postgres://localhost:5432/app DATABASE_PASSWORD=hisar://Work/Postgres%20staging/password GITHUB_TOKEN=hisar://Personal/GitHub/API%20token {%- endcall %} {% call code_block("Running a command with hisar run") -%} $ hisar run --env-file .env -- npm test connecting as app with password <concealed by hisar> ✓ 214 passed {%- endcall %}
hisar mcp

Give your coding agent the keys to run, not to read.

Turn on “Available to agents” for the vaults an agent may use. It finds items by metadata and runs your tests, migrations and deploys with secrets in the environment. You approve each command in Hisar; what comes back to the agent is masked.

Masking is a safety net, not a sandbox: an approved command has the real values. Approve only commands you would run yourself.

Shared vaults

Invite a person by email to a vault. Their device gets the vault key, wrapped to their public key; we never hold it in the clear.
