What it does

Built for the terminal, not just the browser.

SSH agent and git signing

Your SSH keys live in Hisar. Every use asks first.

Point SSH_AUTH_SOCK at Hisar and keep using ssh, git and your editor. The dialog names the app, the processes behind it, who signed it, and the host or commit. Unsigned programs are flagged.

{% call code_block("Point SSH at the Hisar agent", "light", compact=True) -%} export SSH_AUTH_SOCK=~/.hisar/agent.sock {%- endcall %}
hisar run

Commit the .env. It holds no secrets.

Write hisar:// references instead of values. hisar run resolves them in one request, you approve once, and the command gets real values. Nothing is written to disk, and printed values come out concealed.

{% call code_block("Running a command with hisar run", compact=True) -%} $ hisar run --env-file .env -- npm test password <concealed by hisar> {%- endcall %}
hisar mcp

Coding agents use your secrets. They never see them.

Mark the vaults an agent may use. It runs tests, migrations and deploys with secrets in the environment; you approve each command, and output is masked. Masking is a safety net, not a sandbox.

{% call code_block("Adding Hisar to Claude Code", compact=True) -%} $ claude mcp add hisar -- hisar mcp {%- endcall %}
  • {{ icon('phone') }}Approve from your iPhone. Requests arrive end-to-end encrypted and signed. The phone approves; it can't unlock your Mac.
  • {{ icon('link') }}Share links. Send one login to someone without Hisar, with an expiry, a view limit and an optional passphrase.
  • {{ icon('people') }}Shared vaults. Invite people on your server to a vault. Its key is wrapped to each member's public key.

Self-host

One server, three steps.

The server only syncs encrypted data between your devices, so it needs little: a small Linux machine with Docker, where it runs next to Postgres. Everyone who uses it creates an account on your instance with an invite from you.

  1. 01 Start the server {% call code_block("Start the server with Docker Compose", compact=True) -%} $ git clone {{ repository_url }} $ cd hisar/deploy $ docker compose up -d {%- endcall %} Set your domain and a database password first; deploy/README.md walks through it.
  2. 02 Put it behind HTTPS {% call code_block("Caddy reverse proxy configuration", compact=True) -%} # Caddyfile hisar.example.com { reverse_proxy localhost:8080 } {%- endcall %} Any reverse proxy with a valid certificate works: Caddy, nginx, Traefik.
  3. 03 Point the apps at it {% call code_block("Choosing your server at sign-in", compact=True) -%} Sign in → Use a different server… https://hisar.example.com {%- endcall %} The Mac app, iPhone app and CLI all take your server's address at sign-in.

Security model

Running the server doesn't let you read the vaults.

Keys are made on each device. Even the person who runs the server, you included, only sees what's on the left.

What the server sees

  • Account emails, and who can open which vault
  • Item counts, sizes and when they change
  • Devices, IP addresses and app versions

What it never sees

  • Passwords, notes, one-time code seeds, SSH private keys
  • Item titles, URLs and vault names
  • Master passwords, Secret Keys, and the key in a share link
