SSH agent and git signing

Generate or import keys in Hisar; private keys never leave it. ssh, git, VS Code and anything else that speaks the agent protocol reach Hisar through ~/.hisar/agent.sock.

  • Who's asking: app name and icon, the process chain (ssh ← git ← zsh) and its code signature.
  • What for: the host you're connecting to, or the subject and branch of the commit you're signing.
  • Remembered signing: opt in to sign commits from one app and repo for a while without asking again. Free, like the rest of the agent.
  • Unsigned programs get a warning you can't miss.

The CLI and hisar run

On a Mac, hisar works through the running app, which asks you to approve each terminal with Touch ID. On Linux, Windows and servers, the standalone hisar signs in on its own.

  • References look like hisar://<vault>/<item>/<field>; the app copies one for any field.
  • One approval per command shows the command and every secret it reads.
  • Printed values come out as <concealed by hisar>. Use --no-masking for full-screen tools.
  • hisar read prints one value for scripts. SSH private keys are never readable.
{% call code_block("hisar run and hisar read examples") -%} $ hisar run --env-file .env -- docker compose up $ GITHUB_TOKEN=hisar://Personal/GitHub/API%20token \ hisar run -- gh release list $ hisar read hisar://Personal/GitHub/otp 482913 {%- endcall %}

Coding agents, through hisar mcp

hisar mcp is an MCP server for Claude Code, Cursor, Codex, VS Code and any other MCP client. Agents only see vaults you mark “Available to agents”, and every command asks in Hisar, naming the agent and the app it runs in.

ToolWhat the agent getsAsks you
search_itemsTitles, field labels and hisar:// references. Never values or notes.Once per connection
run_with_secretsRuns a command with secrets in its environment; output masked.Every call, showing command, directory and secrets
get_one_time_codeThe current one-time code.Every call; can be allowed for 1 hour
get_secretOne value, in the agent's transcript. Private keys always refused.Every call, for that item

What masking can't do. A command you approve has the real values. It can write them to a file, send them elsewhere or print them encoded. Approve only commands you would run yourself.

Share links

Share a login with someone who doesn't use Hisar. The key lives after the # in the link, so our server never has it. Pick an expiry, a view limit and an optional passphrase; the recipient presses Reveal before anything decrypts. Revoke at any time.

iPhone approvals

When your Mac asks and you're away from it, approve on your iPhone with Face ID. Requests and answers are encrypted and signed end to end; the server only relays them. Your phone approves a request, never unlocks your Mac.

Sharing vaults

Invite someone by email to a vault you own. Their device receives the vault key wrapped to their public key, and the app shows a safety code to compare. People only see who they share with.
